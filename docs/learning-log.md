# Learning Log

A human-readable record of _why_ things in ditto are the way they are:
non-obvious problems solved and measurements that changed a plan, so a later
session inherits the reasoning instead of rediscovering it.

This is a memory aid, **not** a substitute for a check that enforces the
lesson. Whenever one can be enforced — a test, a counter in
[`../perf/baseline.json`](../perf/baseline.json), `go vet` — do that too. This
file only explains the _why_; it never replaces the _how_.

## How to append

- One lesson per line, kept to a single sentence.
- Format: `- [YYYY-MM-DD]: text`
- Newest entries at the bottom. Never rewrite past entries; add a new line if
  something changes.

## Entries

- [2026-08-13]: A counter that measures one thing and is documented as measuring another holds only until the two diverge, which is exactly when it is needed — `sourceParsesPerRelease` counted visits to the `*ast.File` node and called them parses, true only while every parse implied one walk, and it silently kept reporting 12 after parsing was shared and the real answer became 4; counting *distinct* `*ast.File` pointers measures the thing itself, because a shared tree hands every mutator the same pointer and a re-parsed one cannot.
- [2026-08-13]: Git exports `GIT_DIR` and `GIT_INDEX_FILE` to hooks as **absolute** paths in a linked worktree and not at all (or relative) in a plain clone, so anything spawned from a hook in a worktree addresses the real repository instead of its own temporary one — and the misdirected command *succeeds*, which is why it left a stray commit on a live branch and set `core.bare=true` in a shared config without any test failing.
- [2026-08-13]: The dominant per-mutant cost is the fixed overhead of invoking `go test` (measured 700–1100 ms regardless of how fast the suite is), not compilation — recompiling the mutated file measured identically to not changing it at all, while the same tests run from a prebuilt binary took 36 ms, which redirected the optimisation plan from "avoid recompiles" to "avoid invocations".
- [2026-08-13]: Wall clock on a working development machine varied by more than fifty percent for the identical workload while mutant counts stayed exact, so the performance gate is built on integer counters and timings are reported for humans only.
- [2026-08-13]: A source file's relative path is its **identity** — `IgnoreSourceFiles` matches patterns against it and every report prints it — so leaving the host separator in made a pattern written with `/` match nothing on Windows and made the same run name files differently on different machines.
- [2026-08-13]: `T.Parallel` returns without recording anything when its parent has no `barrier`, which is the shape of any hand-built `*testing.T`, and supplying one makes it block forever sending on a nil `signal` channel — so whether a subtest was marked parallel is not observable from outside `testing`, and asserting it needs a seam in the code under test rather than `reflect` and `unsafe`.
- [2026-08-13]: What a run *says* had nothing ratcheting it — `perf/baseline.json` pins what a run costs, so a change could flip a mutant from killed to survived with every unit test still green; the golden release test pins the whole console output of a real run against a throwaway fixture with deliberately mixed verdicts, and it was proved to refuse before it was trusted, by weakening the fixture's own suite and watching it fail.
- [2026-08-13]: AGENTS.md stated that ditto's process spawning strips `GIT_DIR`, `GIT_INDEX_FILE`, `GIT_WORK_TREE`, `GIT_OBJECT_DIRECTORY` and `GIT_COMMON_DIR`, and it never did — the fix from the incident landed in the consuming wrapper, and the doctrine here was written as though ditto had absorbed it, so the claim was the only thing standing where the guard was supposed to be; a decoy test written against the unchanged code reproduced the incident on its first run, taking the decoy repository from one commit to two and rewriting its `user.name` to the intruder's.
- [2026-08-13]: A mutation that does not compile makes the test command exit non-zero, which is exactly how ditto recognises a mutant a test killed — so 7.3% of the mutants it scores over dharness's `internal/` were never executed, from four ordinary causes; `go test` returns 1 for a failing test and 1 for a broken build, so the exit status cannot separate them and only the output text can, which is the one thing a verdict is not allowed to depend on.
- [2026-08-13]: The fixed cost of starting the test command, 750–950 ms per mutant, is what makes a run expensive, and it is a constant while the ratio it produces is not — 2.7× on a package whose suite takes 243 ms and 1.5× on one that takes 1155 ms, from the same mechanism; quoting the ratio without the suite duration beside it says nothing.
- [2026-08-13]: A control that fires and gets explained is worse than no control — a probe answering 0 mutants where 35 were expected was blamed on the shell rewriting an environment variable, a plausible story, when the real cause was a copy made of the wrong repository; the signal was spent and the feeling of having answered it remained.
- [2026-08-14]: `ditto.Gated()` is a no-op under `go test -v` — `release.go` reads `testing.Verbose()` and wraps the gated laboratory in `verboselaboratory`, which implements `Test` and not `TestAll`, so the batch assertion fails and every mutant takes the ordinary path with nothing reporting it; three measurements were made and reported before a `panic` dropped into `TestAll` failed to fire and exposed it, and a second `panic` in `Test` that did fire separated "the laboratory is not in the stack" from "the batch is not forwarded".
- [2026-08-14]: The gated path already runs the instrumented file with no mutant selected, which is the file's own suite, and threw that verdict away with `_ = unselected` — so a suite that fails before anything is mutated reports a perfect score, measured at 4 killed of 4 against 1 of 4 for the same mutants; the measurement was already paid for and reading it cost no run and no compilation, which was predicted before the code was written and held.
- [2026-08-14]: A mutation that fails to compile when written by hand proves nothing about a population until a virus is shown to write it — `comparisonreplace` fires only on `&&` and `||` and replaces an operand rather than a whole comparison, so a fixture whose comparison stood alone could not contain the class at all and reported the two paths agreeing for that reason.
- [2026-08-14]: Two counters can both be correct and answer different questions — a `TestMain` inside the mutated package counts executions of its test binary, 132 for 135 mutants because 3 never compile, while the number the gain is quoted in counts invocations of the test command, 135 against 38; the gated path removes the second and leaves the first, so an instrument aimed at the wrong one fails its control without anything being wrong with the design.
- [2026-08-14]: A mutant's address was already in the tool and nobody had read it — `schemata.Difference` returns the exact byte range and text a mutation replaced, so `path:line:col` cost one call and no parse, while the alternative that looked obvious (carry `token.Pos` from the viruses) meant 15 call sites and a public API break; measured over 135 mutants, 129 of them could not be told apart from another mutant by what ditto printed, and the three hypotheses written to justify the cheap route were all refuted before a second round found that the address plus the replaced text is what separates them.
- [2026-08-14]: Running the binary found two defects the green suite could not — the two identical `Arithmetic` survivors in the golden became distinct addresses, which was the point, and a comparison widened from `>` to `>=` printed as `((nothing) → =)` because a minimal difference has an empty side whenever the mutation inserts rather than swaps; naming the operation instead of rendering an empty arrow was a change to the deliverable that only reading the deliverable could have prompted.
- [2026-08-14]: A counter nobody prints is a counter that cannot go wrong in front of anyone — `Gated` and `FellBack` were exact and correct the whole time while `ditto.Gated()` was a no-op under `go test -v`, and the defect survived three measurements because a run that gated every mutant and one that gated none produced identical output; printing them first is what made "before" measurable at all, and the numbers then came out none of 7 under `-v` against a control of 4 of 7 without it.
- [2026-08-14]: The same defect is still one interface away and only ordering hides it — `VerboseTemporaryDir` implements `New` and not `RemoveAll`, so the sandbox cleanup works solely because `reclaimSandboxes` runs twelve lines before the verbose block wraps the temporary directory; a decorator that silently drops an optional interface is refused by nothing in this codebase, and the comment that explains the ordering is a sentence rather than a guard.
- [2026-08-14]: Event-driven CI has never run in this repository and two releases were published believing it had — ditto is a fork of gtramontina/ooze, GitHub disables Actions on forks for `push` and `pull_request` whatever the workflow says, and `actions/permissions` still reports enabled:true; a 43-commit push and a pull request produced zero runs, every run in the repository's history carries `event: workflow_dispatch`, and `mutation.yml` has no dispatch trigger at all so it cannot run by any route.
- [2026-08-14]: A local `origin/main` is a claim, not a fact — the SSH key was absent so `git fetch` could not correct it, and the stale ref put the unreleased range at 60 commits when it was 43 and made two published releases look unpublished; `gh api repos/<owner>/<repo>/commits/main` answered in one call what the local ref got wrong.
- [2026-08-15]: The API can report a system healthy while none of it fires — `actions/permissions` said enabled, every workflow said active, no workflow carried a `paths:` filter, and yet ten runs of ten were `workflow_dispatch`; the cause was only established by a probe with a kill line, a commit pushed straight to `main` touching `.github/workflows` that produced zero runs over two minutes, and until that ran the claim written into the skill, this log and a published release note was an inference wearing a diagnosis's clothes.
- [2026-08-15]: A workflow run reports `completed` when its only job was skipped — adding `workflow_dispatch` to the mutation gate left `if: github.event.workflow_run.conclusion == 'success'` in place, which is null on a dispatch, so the run looked green at a glance and had done nothing; the conclusion that means anything belongs to the job, never to the run.
- [2026-08-15]: Two of ditto's own test fixtures encoded a red suite without meaning to — `observingRunner` and `silentRunner` each answered `result.Ok`, which is how the tool reports that the command FAILED, on every single call; nothing objected until a guard was written that refuses to score against a baseline that is red before anything is mutated, and that two fixtures had quietly described the broken state is the clearest evidence that nothing was watching for it.
- [2026-08-15]: A counter can be blind to the cost it was built to watch — every `laboratoryRuns*` counter substitutes a stand-in laboratory, so it measures how many runs `Release` *asks* for and can never see one the laboratory makes on its own; adding the baseline check moved no recorded number at all, and the cost only became visible once a counter measured invocations through the laboratory ditto actually ships.
- [2026-08-15]: A note can hold its discipline through every hypothesis and lose it in the closing sentence — this one measured three hypotheses with controls and then argued from wall clock and one observation per side that "5.46 seconds was not the cost of testing 431 mutants"; the counters said the same thing far better once they were asked, 431 killed and 0 survived against 329 killed and 102 survived over an identical population, and the wall-clock line was withdrawn rather than kept as a second opinion.
- [2026-08-15]: Replication caught nothing wrong and was still worth every minute — two dispatched runs of the full gate agreed to the integer, three rotated rounds on a scoped subset agreed to the integer, and the strongest control was one nobody planned: the scoped triple 69/58/11 matched a measurement made earlier the same day by a different harness, on a different revision, for a different question.
- [2026-08-28]: Three rounds of argument over which denominator a mutation score should use were settled in an afternoon by reading the field instead — "unjudged" is not one class but three, each with an answer established since 1997: a mutant that does not compile leaves the numerator AND the denominator because the kill predicate is undefined for a program that does not exist, a timeout is a KILL reported as its own reason, and a suspected equivalent counts as survived under a metric renamed to a stated lower bound; the 22% of unearned kills measured here was therefore never one problem, and the 10 non-compiling mutants inside it are a defect of the generator with an external benchmark (Major 1.8%, PIT 0%) rather than a scoring question at all.
- [2026-08-28]: The literature had already answered the larger question too, and against the tool — Google abandoned the mutation ratio in IEEE TSE 2021 as "neither concrete nor actionable", fewer than 5% of mutants are subsuming and the all-mutants ratio does not track the subsuming one, the correlation with real faults is weak once suite size is controlled, and below a high threshold the number is disconnected from fault revelation entirely; ditto's gate runs at 0.5, which is below, so a score was being gated in exactly the range where it carries no signal.
- [2026-08-28]: A claim from a systematic review was wrong and checking it paid better than accepting it would have — the review reported `go test` exiting 2 for a package that does not compile, and on go1.27 everything exits 1, but the check turned up `go test -json` emitting `Action:"build-fail"` and a `FailedBuild` field that never appear when a test fails for real, which is the cheap structured route three rounds of argument had priced at +25% per mutant.
- [2026-08-29]: A ratchet that only ever records is a changelog with a threshold on it — `mutantsPerReleaseOnThisRepository` fired six times in one session and every single time the response was to write the new number down, never to change a decision, which is the owner's own test for a vanity metric failing on a counter added three commits earlier to catch vanity metrics; the counters that survive that test name something to delete, and the ones that do not are diagnosis and belong without a threshold.
- [2026-08-29]: The performance question has exactly one decision in it and it is binary — does the gate finish — and no count of mutants predicts it, because cost per mutant is not uniform: a killed mutant stops at the first failure under -failfast, a survivor pays the whole suite, and one stopped by the deadline pays the deadline; a count multiplied by an average is the same vanity metric in a new hat.
- [2026-08-29]: Two independent reviews of the 2021-2026 literature agreed that there is no accepted performance metric for a mutation run at all — eighteen catalogued cost metrics and not one of them is the absolute cost of a run, the mutant count as a surrogate is a documented threat to validity at 44% average error that GROWS with repository size, and no tool surveyed gates a build on cost rather than on score; the counters here were not a bad choice among good ones, they were a number the field has established cannot be had.
- [2026-08-29]: The one published model that predicts a mutation run's duration assumes uniform per-mutant cost and its own measurements refute it — timed-out mutants took 93% of the analysis time on one of its six subjects — so the killed-early / survivor / timeout distinction is implemented everywhere and modelled nowhere, and the instrument for measuring it here came out of the accuracy work rather than the performance work: internal/verdict records why each mutant died, which is exactly the partition nobody models cost by.
